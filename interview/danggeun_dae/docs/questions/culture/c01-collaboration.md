# C1. 협업/설득 스토리

> 컬처핏/경험 질문

---

## 질문

"분석가가 기술적으로 불가능하거나 비효율적인 데이터 추출을 요청할 때 어떻게 설득하겠는가?"

---

## 핵심 답변 포인트 (30초 요약)

```
3단계 접근:
1. 의도 파악 - "어떤 비즈니스 문제를 해결하려고 하나요?"
2. 대안 제시 - "이 방식은 6시간, 이렇게 바꾸면 10분"
3. 장기적 해결 - 데이터 마트/셀프서비스 제공
```

---

## 상세 답변

### 3단계 접근법

**1단계: 요청 의도 파악**

```
질문:
- "이 데이터를 어떤 비즈니스 결정에 사용하시나요?"
- "어떤 인사이트를 얻고 싶으신가요?"
- "결과를 언제까지 필요하신가요?"

목적:
- 실제 필요한 데이터가 요청된 데이터와 같은지 확인
- 긴급도 파악 (샘플링으로 가능한지)
- 근본적인 문제 파악 (반복 요청인지)
```

**2단계: 대안 제시**

| 원래 요청 | 문제점 | 대안 | 이점 |
|-----------|--------|------|------|
| 전체 5년 거래 데이터 | 50GB, 6시간 | 최근 1년 샘플링 | 500MB, 10분 |
| 실시간 집계 | 시스템 부하 | 배치 집계 + 증분 | 성능 보장 |
| 정규화된 10개 테이 JOIN | 복잡성 | 데이터 마트 1개 | 간단한 쿼리 |
| 미정의 지표 | 혼란 | 지표 정의 협의 | 일관성 확보 |

**제시 방법**:
```
"이 방식은 6시간이 걸리는데, 이렇게 바꾸면 10분에 가능합니다.

원래: 전체 거래 데이터 (2019-2024)
대안: 최근 1년 + 주요 카테고리만 샘플링

탐색적 분석이라면 샘플링으로 충분할 것 같습니다.
전체 데이터는 검증 단계에서 추출하겠습니다."
```

**3단계: 장기적 해결책**

```
반복되는 요청이라면:

1. 데이터 마트 구축 제안
   - 자주 쓰는 조합을 미리 집계한 테이블
   - 분석가가 직접 쿼리 가능

2. 셀프서비스 대시보드 제공
   - Looker/Tableau 등으로 필터 제공
   - 실시간 데이터 조회 가능

3. dbt로 문서화
   - 자주 쓰는 SQL을 dbt 모델로 공유
   - 분석가가 수정/확장 가능
```

## 꼬리 질문 및 답변

### Q: PO가 "지금 당장 필요하다"고 하면?

**답변**:
```
"긴급도를 먼저 확인합니다.

1. 긴급성 검증
   - '이 결정이 지금 당장 필요한가요?'
   - '내일 아침까지 vs 지금 당장'

2. 단계적 제공
   - 1시간 내 샘플링 데이터 제공
   - '탐색용으로 먼저 써보시고, 
     검증이 필요하시면 정확한 값을 밤에 추출하겠습니다'

3. 장기적 개선
   - '이런 긴급 요청이 자주 있으신가요?'
   - 셀프서비스 도구 제공 제안

핵심: 협조적이면서도 데이터 품질을 해치지 않는 균형"
```

### Q: 분석가가 "이 데이터는 반드시 필요하다"고 우기면?

**답변**:
```
"객관적 기준 제시:

1. 비용 투명화
   - '이 쿼리는 50GB를 스캔해서 $2.5가 듭니다'
   - '1주일에 3번씩 실행하면 월 $30'

2. 성능 영향 설명
   - '이 쿼리가 실행 중일 때 다른 쿼리가 느려집니다'
   - '실제 사용자에게 영향이 갈 수 있습니다'

3. 대안의 근거
   - '작년 동일 분석에서 샘플링과 전체의 차이는 2%였습니다'
   - '이 정밀도로 충분하지 않을까요?'

4. 에스컬레이션
   - 여전히 불가하다면 팀 리더와 논의
   - 데이터 거버넌스 가이드라인 참조"
```

### Q: 기술적 불가능이 아닌 '귀찮음'이라면?

**답변**:
```
"차이를 인식하고 접근법 조정:

1. 동기 부여
   - '이 데이터로 어떤 임팩트를 만들 수 있을까요?'
   - '사용자 경험 개선에 기여하는 부분입니다'

2. 프로세스 개선
   - 반복 작업 자동화 제안
   - 템플릿/스니펫 제공

3. 협업 강화
   - pair programming 제안
   - SQL 리뷰 및 피드백

하지만:
- 기술적으로 불가능한 것은 단호하게
- 귀찮음은 협업으로 해결"
```

## 실전 팁

### 대화 템플릿

```
[거절할 때]
"이 요청은 기술적으로 [이유]로 어렵습니다.
대신 [대안]을 제안드립니다.
[대안의 이점]이 있습니다.
어떻게 생각하시나요?"

[지연할 때]
"이 요청은 [시간]이 소요됩니다.
급하시다면 [단축안]을 먼저 제공하겠습니다.
정확한 값은 [시간] 후에 드리겠습니다."

[협업할 때]
"함께 SQL을 작성해보시겠어요?
dbt로 공유하면 다음에는 직접 수정 가능합니다."
```

### 면접에서 강조할 점

- **business-first**: 기술적 제약보다 비즈니스 가치 우선
- **collaborative**: 거절이 아닌 대안 제시
- **proactive**: 반복 요청에는 근본적 해결책 제시
