# C2. 비즈니스 가치 판단

> 컬처핏/경험 질문

---

## 질문

"기술적으로는 완벽하지만 비즈니스적으로는 큰 의미가 없는 프로젝트를 맡게 된다면 어떻게 하겠는가?"

---

## 핵심 답변 포인트 (30초 요약)

```
3단계 접근:
1. 가치 재검토 - "누가, 어떤 결정에 사용하나요?"
2. MVP 검증 - 작게 시작해서 가치 확인
3. 역할 확대 - 단순 제공을 넘어 인사이트 도출
```

---

## 상세 답변

### 3단계 접근법

**1단계: 프로젝트의 비즈니스 가치 재검토**

```
질문:
- "이 데이터를 누가 사용하시나요?"
- "어떤 비즈니스 결정에 활용되나요?"
- "지금 없으면 어떤 문제가 있나요?"

목적:
- 실제 사용자가 있는지 확인
- 사용되지 않는다면 과감히 중단 제안
- 잘못된 요구사항이었다면 재정의
```

**2단계: 작은 단위로 쪼개서 가치 검증**

```
MVP 접근:
- 전체가 아닌 핵심 20%만 먼저 제공
- 피드백 받고 확장 여부 결정
- 2주 스프린트로 가치 검증

예시:
"전체 데이터를 2개월 개발하는 대신,
먼저 핵심 지표 3개만 1주일에 제공하겠습니다.
사용해보시고 확장 여부 결정해주세요."
```

**3단계: DAE의 역할 확대**

```
단순 데이터 제공을 넘어:
- "제가 보기에는 이런 패턴이 있습니다"
- "이 인사이트는 어떠세요?"
- "이 데이터로 이런 의사결정이 가능합니다"

제안:
- 인사이트 도출 세션 제안
- 데이터 리터러시 트레이닝
- 셀프서비스 도구 제공
```

---

## 꼬리 질문 및 답변

### Q: 이미 진행 중인데 중단 요청이 오면?

**답변**:
```
"산출물 자산화 + 프로세스 개선:

1. 산출물 정리
   - 개발된 코드, 문서 저장
   - 재사용 가능한 모듈 분리
   - 향후 유사 프로젝트 참고자료로 활용

2. 중단 사유 문서화
   - 왜 중단되었는지 기록
   - 다음부터는 초기에 비즈니스 목표 명확히

3. 프로세스 개선 제안
   - 프로젝트 시작 전 '가치 검증' 단계 추가
   - 2주 MVP 제도 도입
   - 데이터 요청 템플릿화"
```

### Q: 상사가 시켜서 할 수밖에 없는 상황이라면?

**답변**:
```
"신중하게 의견 제시:

1. 우려사항 전달
   - '이 프로젝트는 기술적으로 완벽하지만,
     실제 사용될지 우려됩니다'
   - '2주 MVP로 먼저 검증하는 것이 어떨까요?'

2. 대안 제시
   - '대신 [더 가치 있는 프로젝트]를 제안드립니다'
   - 데이터로 근거 제시 (ROI 비교)

3. 최종 결정 존중
   - 팀 결정이라면 최선을 다해 수행
   - 하지만 사용 실태 모니터링 후 피드백

핵심:
- 반대가 아닌 우려 제시
- 데이터로 근거
- 팀 결정 존중"
```

### Q: 기술적 도전 vs 비즈니스 가치 충돌 시?

**답변**:
```
"균형점 찾기:

케이스 1: 기술적 도전이 미래 가치가 있다면
- POC(Proof of Concept)로 기술 검증
- 실제 적용은 비즈니스 준비될 때

케이스 2: 순수한 기술적 호기심이라면
- 사이드 프로젝트로 전환
- 또는 컨퍼런스/블로그 주제로 활용

케이스 3: 팀의 기술 성장을 위해서라면
- 20% 시간(R&D 시간) 활용
- 단 비즈니스 프로젝트와 명확히 분리

결정 기준:
- '1년 후 이게 회사에 어떤 도움이 되나?'
- 답이 없다면 우선순위 하락"
```

## 실전 팁

### 프로젝트 평가 매트릭스

```
                    높은 비즈니스 가치
                           │
           [우선순위 1]    │    [우선순위 2]
           (즉시 실행)     │    (계획 후 실행)
                           │
낮은 기술 ─────────────────┼───────────────── 높은 기술
난이도                     │                 난이도
                           │
           [우선순위 3]    │    [우선순위 4]
           (빠른 승리)     │    (보류/사이드)
                           │
                    낮은 비즈니스 가치
```

### 면접에서 강조할 점

- **pragmatism**: 기술적 완벽함보다 실제 임팩트
- **risk management**: 실패 가능성 있는 프로젝트 조기 감지
- **value validation**: MVP로 가치 검증하는 습관
