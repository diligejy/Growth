# 당근 테크 블로그 인사이트

> 실제 당근 데이터 팀의 고민과 방향성

---

## 핵심 인사이트 (3줄 요약)

1. **데이터 가치화 팀**: 분석가가 "뛰어놀 수 있는 환경"을 만드는 것이 목표
2. **수작업 라벨링 지양**: 자동으로 쌓이는 데이터(신고/제재) 기반 모델링
3. **실제 세계 모델링**: 데이터를 변형하지 않고 현상 그대로 수집/학습

## 1. 데이터 가치화 팀 구성 및 역할

### 팀원 역할 (2022년 기준)

| 이름 | 역할 | 핵심 활동 |
|------|------|-----------|
| **매튜** | 데이터 분석가 | 데이터 분석가가 뛰어놀 수 있는 환경 고민 |
| **띠오** | 데이터 분석가 | 팀원이 매 순간 더 좋은 결정을 할 수 있는 방법 탐구 |
| **샘** | 데이터 분석가 | 목적 조직 문제 해결, 실험을 통한 학습 |
| **이안** | 소프트웨어 엔지니어 | 데이터 활용 기술적 문제 해결 |

| **루크** | 데이터 엔지니어 | 편리하고 올바른 데이터 만들기, Beam Pipeline |
| **헨리** | 소프트웨어 엔지니어 | **실험플랫폼, 이벤트 로깅 인프라, 데이터 파이프라인** |

### 팀 비전

> "사용자에게 더 좋은 경험을 주기 위해 데이터를 다룬다"

- WAU 1,200만, MAU 1,800만 (2022년 8월 기준)
- 각 팀이 만드는 기능이 사용자에게 좋은 경험인지 알기 어려움
- 데이터를 통해 더 좋은 경험을 주는 것이 팀의 가치

## 2. 데이터 모델링 철학

### 수작업 라벨링의 한계와 극복

**문제 상황**:
```
초기: 수작업으로 중고거래 글 라벨링 → ML 모델 학습
↓
성장: 매달 12% 이상 글 증가
↓
한계: 수작업이 따라갈 수 없음, 모델 성능 저하
```

**해결 방안**:
```
자동 수집 데이터:
├── 사용자 신고 데이터
└── 운영자 제재 데이터

→ 지속해서 쌓이는 데이터 기반으로 모델 자동 학습
→ 운영 자동화 고도화
```

### 실제 세계 데이터 모델링

**핵심 원칙**:
> "특정 도메인 모델에 맞게 데이터를 변형하기보다, 실제 현상을 데이터로 수집하여 그대로 학습"

**사례 1: 중고거래 글 예측 모델**
```
학습 데이터:
├── 운영자 제재 데이터 (정확하지만 모든 글 볼 수 없음)
└── 사용자 신고 데이터 (부정확하지만 모든 글 대상으로 발생)

모델링:
- 운영자 제재만 학습 → 일반 게시글 구분 못함 (정확도 저하)
- 사용자 신고 + 일반 게시글 샘플링 → 잘 학습됨

인사이트:
"사용자 신고 데이터를 부정확한 노이즈가 아닌, 
실제 사용자의 신고할 가능성을 예측하는 것으로 생각"
```

**사례 2: 피드 랭킹 모델**
```
사용자에게 실제 노출되고 영향을 끼치는 정보를
노출되는 상황과 맞게 최대한 수집하여 반응 여부 학습

→ 실제 현상을 그대로 모델링
```

## 3. DAE 면접에 적용하기

### 질문: "당근의 데이터 모델링 철학은?"

**답변**:
```
"당근은 '실제 세계 데이터 모델링'을 중요하게 생각합니다.

수작업 라벨링의 한계를 인식하고,
사용자 신고와 운영자 제재처럼 자연스럽게 쌓이는 데이터를 
학습 데이터로 활용합니다.

ML 모델은 특정 도메인에 맞게 데이터를 변형하기보다,
실제 현상을 데이터로 수집하여 그대로 학습하는 방식이
더 효과적이라고 판단합니다.

예를 들어 중고거래 글 예측 모델은
사용자 신고를 '부정확한 라벨'이 아닌
'신고할 가능성 예측'으로 모델링하여 성능을 유지합니다."
```

### 질문: "데이터 가치화 팀의 목표는?"

**답변**:
```
"데이터 분석가가 '뛰어놀 수 있는 환경'을 만드는 것입니다.

구체적으로:
1. 실험플랫폼 제공 (A/B 테스트 인프라)
2. 이벤트 로깅 인프라 (데이터 수집 자동화)
3. 데이터 파이프라인 (분석가가 쓰기 좋은 데이터 환경)

이를 통해 당근의 다양한 팀이 사용자에게 
더 좋은 경험을 주는 기능을 만들 수 있도록 지원합니다."
```
